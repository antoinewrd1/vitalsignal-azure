# VitalSignal — public health surveillance lakehouse on Azure

An end-to-end **data engineering + analytics engineering + ML engineering + AI
engineering** project: synthetic electronic case reports (eCR) flow through a
medallion lakehouse, a dbt warehouse, an outbreak-detection model tracked in
MLflow, and an LLM layer (structured extraction + grounded RAG) with a gated
eval harness. Target platform is **Azure** (ADLS Gen2, Azure Databricks, Azure
ML, Azure OpenAI, Azure AI Search); every layer also runs **fully locally with
zero cloud dependencies**, which is what CI does on every push.

The domain is deliberate: it extends real production experience running a
statewide eCR pipeline (HL7/FHIR, 360K+ clinical records/year) at a state
health department: the synthetic feed here mimics that shape.

```
landing (NDJSON, HL7v2-style)                                 [generate/]
   └─ bronze  append-only raw + lineage, idempotent            [ingest/]      PySpark
       └─ silver  parsed, conformed, quarantined, deduped      [transform/]   PySpark
           └─ gold  dims + zero-filled daily fact + z-score    [dbt/]         dbt (DuckDB dev / Databricks prod)
               ├─ features → train → registry → batch score    [ml/]          sklearn + MLflow / Azure ML
               └─ extraction • RAG • eval gates                [ai/]          Azure OpenAI / offline stub
```

## What is verified vs. what is claimed

| Claim | Status |
|---|---|
| Full pipeline runs end-to-end (`make pipeline`) | **Verified locally and in CI** — generate → bronze → silver → dbt (29/29 tests) → features → train → score → RAG index → eval gates |
| Bronze re-runs are no-ops (idempotency) | **Verified** — control-table anti-join; second run ingests 0 rows |
| Model beats the z≥3 aberration rule at equal alert budget | **Verified on synthetic labels only** — P 0.83/R 0.88 vs P 0.19/R 0.23 at ~8 alerts/wk on a 75-day temporal holdout. Labels are injected by this repo's generator; this validates the pipeline, **not** field performance |
| No feature leakage | **Tested** — `tests/test_features_leakage.py`; dbt baseline window excludes the current day by construction |
| LLM extraction & RAG grounding | **Harness verified with the deterministic offline backend**; real-model numbers require `VS_LLM_BACKEND=azure_openai` and are not claimed here |
| Delta Lake writes | **Not verified in this repo's CI** (Parquet locally; `VS_TABLE_FORMAT=delta` is the config-switched Databricks path) |
| Azure deployment (`infra/main.bicep`, job specs) | **Written, not deployed** — compiles the intended architecture; no live-subscription run is claimed |

## Quickstart (local, no Azure account)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
make pipeline        # ~4 min on a laptop; every step prints what it did
make test            # 21 unit tests (Spark parsing, leakage guards, AI contracts)
```

Outputs land in `_lake/` (medallion layers), `_lake/gold/warehouse.duckdb`
(marts), `_mlruns/` (MLflow), and `_out/` (train + eval reports).

## Running against Azure

1. `az deployment group create -g rg-vitalsignal -f infra/main.bicep -p adminObjectId=$(az ad signed-in-user show --query id -o tsv)`
2. Set `VS_BACKEND=azure` plus the variables in `.env.example`; storage paths
   become `abfss://…` automatically (`src/vitalsignal/config.py` is the only
   file that knows the difference).
3. Data pipeline → `orchestration/databricks_job.json` (nightly, task graph =
   the Makefile). Training → `azureml/train_job.yml` (weekly, logs to the
   workspace via `VS_MLFLOW_TRACKING_URI=azureml://`).
4. LLM layer → `VS_LLM_BACKEND=azure_openai` (Entra ID auth by default; the
   Bicep sets `disableLocalAuth: true` on the OpenAI account to match).

## Honest limitations

- **All data is synthetic**, generated by `generate/synthetic_ecr.py`. The HL7
  messages are structurally faithful but not conformant; the guidance corpus in
  the RAG layer is written for this project and is **not** authoritative
  CDC/VDH text.
- **ML metrics are a pipeline test, not an epidemiology result.** The model
  detects the generator's injected outbreak windows. The interesting, real
  finding is *why* it beats the z-score rule: sustained outbreaks contaminate
  their own 28-day baseline, blinding the rule mid-outbreak — a documented
  weakness of naive aberration detection that the trailing-count features
  sidestep.
- **The offline LLM stub is regex.** Eval numbers under `llm_backend: "fake"`
  validate the harness and vocabulary mapping only; the report labels its
  backend for exactly this reason.
- The BM25 relevance floor is calibrated on this corpus; Azure AI Search's
  semantic ranker replaces it in production.
